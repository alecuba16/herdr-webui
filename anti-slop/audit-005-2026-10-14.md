## Findings

1. **R-32 HIGH (fixed)**: `.notes-title-input` had `outline: 0` with no
   replacement and `.notes-row` (role=button, tabindex=0) had no focus
   style. Fixed in the focus-visible commit: both use the app-standard
   `var(--focus-ring)` box-shadow on `:focus-visible`, matching
   `controls.css` button/input rules. Row keyboard activation was
   already covered by the global span-button delegation in bindings.js
   (`[role="button"][tabindex="0"]`), so Enter/Space opens notes.
2. **R-02 LOW (verified clean)**: no em dashes in any new code, test,
   doc, or commit text. Scanned all touched files; the hits in
   features.md/release-notes.md are pre-existing lines.
3. **R-26 PASS**: every control is real: new note (POST), per-row open
   (editor mount), per-row delete (DELETE, stopPropagation so the row
   never opens), title input (PUT on change), language select (PUT +
   editor remount), back (conditional flush), clear-all (danger
   confirm + POST). The save-state button is a disabled status
   indicator showing Saving/Saved, not an interactive control.
4. **R-27 PASS**: empty ("No notes yet. Create one to get started."),
   loading ("Loading notes..." with the loaded guard), error
   (`notes-error` block on API failure) all render; CSS classes exist.
5. **R-35 PASS**: click-through evidence from the real e2e (10/10
   checks over the served bundle with real CodeMirror, real API, real
   persistence): rail hosting, empty state, create-editing, list row,
   editor mount, persistence + reload, delete, clear-all confirm.
   Rust route tests (4) over the real router; 709/709 and 1186/1186
   suites green after every commit.
6. **R-36/R-17 PASS**: docs claim only verified behavior (600ms debounce
   is `SAVE_DEBOUNCE_MS = 600`, caps are the tested server constants,
   14 languages is the LANGUAGES array length, "survives restarts" is
   the `notes_sidecar_survives_state_rebuild` test). No invented stats.
7. **R-33 PASS**: no patch scripts; everything built in source
   (notes.rs, notes.js, notes.css, app.html rail button).
8. **R-03 PASS**: desktop-only v1 is the approved default; the rail
   button and panel live in the desktop bundle only, mobile lists the
   gap in development.md parity section. Mobile layout unaffected.
9. **R-25 PASS**: all colors go through theme tokens first
   (`var(--accent-soft, ...)`, `var(--danger, ...)`,
   `var(--focus-ring)`); 16 `var(--token)` references and 3 fallback
   literals, all in the codebase-standard `var(--token, fallback)`
   pattern (same as controls.css `var(--danger, #f38ba8)`). No color
   bypasses the token system. `--text-dim` uses the standard
   `var(--text-dim, inherit)` fallback pattern, so the dimmed meta
   text inherits the panel's AA-passing text color when the token is
   undefined.
10. **R-37 PASS**: direction existed before implementation:
    `docs/ux/notes-rail-design.md` (committed `cbc31cd`), validated
    three rounds including a Node VM run of the real CodeMirror bundle.
    The four approved defaults (confirm-free per-note delete,
    danger-confirmed clear-all, desktop-only v1, rail-click-only open)
    governed the behavior decisions.
11. **R-31 PASS**: written reasons for major decisions are in the design
    doc (600ms debounce vs the 180ms search precedent because payloads
    are bigger; sidecar vs webui-settings.json so note writes never
    rewrite auth config; path-driven highlighting so parse cost is paid
    only while editing).
12. **R-15/R-16 PASS**: buttons say "+ New", "Clear all", "Back to
    list"; docs use concrete language, no buzzwords.
13. **R-19 PASS**: no decorative animation; the delete affordance uses
    opacity on hover/focus-within, a functional reveal.
14. **R-14 PASS**: no card grid; the panel is a list whose rows reflect
    content (title, language chip, timestamp, delete), matching the
    Files/Git/Search rail siblings.
15. **R-04 PASS**: one new icon use, the pencil rail button, wired the
    same way as the file/git siblings: `setupRightSidebarRail()` in
    core.js injects `appIcon("pencil")`, base.css masks
    `.app-icon-pencil` with the existing `/assets/icons/pencil.svg`.
    No new icon file, no emoji decoration.
