## Post-audit validation round

A second validation pass after the verdict ran live probes and
re-read every save path. Findings:

1. **R-26/R-32 HIGH (fixed)**: a failed PUT (note deleted from another
   client, 500) set state.error but the editing view never rendered it.
   The pre-fix failure path called renderPanel() while state.saving
   was still true, so the immediate symptom was a stuck Saving... label
   and a CodeMirror remount under the cursor; on any later re-render the
   button read Saved while back/close dropped the edit as if persisted.
   Fixed: failures paint a .notes-editor-error line (danger token) and
   flip the button to Save failed without touching the editor container
   (a repaint would remount CodeMirror mid-edit), and the edit stays
   dirty so back and close retry the flush. A follow-up pass also made
   back PUT directly instead of going through flushSave, which refuses
   while a save is in flight and would drop that debounce window's
   keystrokes. Three vm tests pin the failure, retry, and title-failure
   paths; e2e re-ran green after both changes.
2. **R-35 PASS**: live auth probe (scripts/e2e/notes-auth-probe.sh)
   boots the real binary with credentials and the localhost bypass off
   and asserts all five method+route combos return 401, then logs in
   and confirms the session is served. One probe-design lesson: the
   loopback default ships localhost_no_auth true, so the probe pins
   credentials + bypass off. POST/PUT send the real JSON shape so they
   reach the handler auth check; axum's Json extractor ordering (415
   before auth) is app-wide, not notes-specific.
3. **R-25 PASS (recheck)**: notes.js templates escape id, title, and
   language through escapeHtml before every interpolation; the editor
   title arrives via DOM property assignment; LANGUAGES values are
   static. No injection sink in the panel.
4. **R-36 PASS (recheck)**: every doc constant matches the source:
   600ms debounce (SAVE_DEBOUNCE_MS), 200/200/32KB caps, 14 languages,
   notes.json next to webui-settings.json, newest-first sort, no
   polling in the module.

## Third validation round

Remaining untested claims probed directly:

1. **R-36 PASS (cap units)**: the title cap counts characters
   (chars().count()), not bytes, so the "200-character" doc claim is
   accurate for accented and CJK titles. Pinned with 201/200 multibyte
   cases in the caps test (ASCII alone could not distinguish char vs
   byte counting). Content is a 32KB byte budget and the docs say 32KB.
2. **R-35 PASS (corrupt sidecar)**: new test pins that a corrupt
   notes.json boots to an empty store without panicking and the next
   save rewrites the garbage.
3. **R-35 PASS (live restart)**: new probe script boots the real
   binary, creates a note through the API, kills the process, reboots
   on the same XDG dir, and asserts title and content survive. The
   "survives server restarts" doc claim now has process-restart
   evidence, not just load_notes/save_notes unit tests and the e2e's
   client-reload check.
4. **R-35 PASS (id uniqueness)**: fresh_note_id is pinned unique across
   a 1000-iteration loop (same contract as auth tokens).
5. **R-03 PASS (mobile exclusion recheck)**: the mobile bundle ships no
   notes asset, no rail button, and no HerdrNotesPanel reference; the
   only mobile "notes" hit is a coincidental example filename in the
   file browser sheet.
