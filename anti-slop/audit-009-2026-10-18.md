## Findings

1. HIGH (R-26, C-2): dead selector `.mobile-keybar-sendkey[aria-pressed="true"]`
   in app.css. The `key()` builder emits `aria-pressed` only for the one-shot
   Ctrl key; C⏎ never carries the attribute, so the pressed variant could
   never render. A "works or not exist" control rule with no reachable state.
   FIXED: dropped the dead variant; the accent border+text on the resting
   key is the send-action marker, matching the documented intent.

2. HIGH (R-25, C-4): light theme text contrast. `--accent` `#1957d2` on
   `--panel2` `#ccd0da` = 4.08:1, under the 4.5:1 floor for 14px text.
   The accent-colored C⏎ key would ship a readable-in-dark-only label.
   FIXED: sendkey text uses `var(--fg)` with the accent kept on the border
   only; accent-on-panel2 contrast only carries the 3:1 non-text rule
   (4.08 passes for borders). Dark theme unchanged.

3. MEDIUM (R-25, C-4, pre-existing): light theme defines no `--danger`,
   so `.mobile-keybar-danger` and friends fall back to `#f38ba8`
   on `#ccd0da` = 1.5:1. User approved fixing it with this diff.
   FIXED: added `--danger: #a61b1b` to `body.light` (the existing
   `--git-deleted-color` red, 4.87:1 on panel2, 6.65:1 on bg); the
   dark fallback `#f38ba8` stays (7.08:1 on dark panel2). The same
   fallback paints ^C, ^D and the composer error note, all now AA in
   light mode.

4. LOW (R-31): sendkey accent now exists as border-only + the existing
   `.mobile-keybar-key[aria-pressed="true"]` filled variant for armed Ctrl
   keeps one accent moment per row. Reason written in the CSS comment:
   chord key is the send action, same accent the Send button uses.

Interpretation re-check (work started before the intent settled): every
guessed reading was later checked against ground truth. The chord bytes
match wterm's own encoder (`\x1B[13;5u` press, modifiers 1+Ctrl=5; legacy
flags 0 sends `\r` on press and nothing on release, so one frame equals
press+release). `term.wterm.bridge.kittyKeyboardFlags()` is the same
accessor composer.js uses, and the real strip helpers
(stripTerminalQueryReplies/stripTerminalMouseReports, loaded via require)
pass `\x1b[13;5u` through untouched with empty carry. Residual gap, shared
with every pre-existing keybar key: no live headless tap of C⏎ through a
real pane; the path is covered by vm byte tests plus the real-function
checks above.
