# Audit 008 - TUI cleanup parity (branch-too, gated rescan, parallel deletes)

Date: 2026-10-16
Mode: AFTER (session override). Scope: uncommitted TUI diff on top of
`04ffe5a` (webui cleanup delete flow) + `2327d0a` (audit 007).
Files: `src/tui/panels/git/cleanup.rs`, `src/tui/panels/git/mod.rs`,
`src/tui/mod.rs`, `src/tui/render/mod.rs`, `src/tui/web_api.rs`,
`src/tui/panels/tests.rs`, `src/tui/tests/mod.rs`, docs.

The TUI is a keyboard-only terminal UI: no color/gradient/glass/icon
surface applies. The gate ran over copy (prompts, hints, footer),
interaction completeness, and honesty of the rendered state.

## Findings

1. HIGH (R-26, C-2): `cleanup_failures` was read by the confirm arm
   (`self.error`) but never written, so per-item delete failures were
   dropped on the floor: the user saw a silent no-op. Fixed: the
   delete-selected join loop stores the failures on the panel, each new
   run clears them first. Regression test:
   `cleanup_delete_selected_records_per_item_failures` (port-1 stub
   rejects every delete; asserts the recorded failure names the item).
   FIXED.

2. HIGH (R-26, C-2): `cleanup_delete` (old single-item path) became
   production-dead when the confirm arm moved to
   `cleanup_delete_selected`; only tests kept it alive, so the real
   single-row flow was untested. Removed it and rerouted the
   routes-integration test through `cleanup_delete_selected`
   (unmarked delete acts on the cursor row, the same semantics the
   confirm prompt uses). FIXED.

3. MEDIUM (R-31, C-1): the cleanup rows showed no mark state while
   Space silently toggled it (webui checkbox counterpart invisible in
   the TUI), and neither the pane title nor the footer advertised the
   Space key, so the feature was undiscoverable. Fixed: marked rows
   show the `*` accent prefix (same gesture as the log view's
   shift-click marks, kept consistent on purpose), the pane title and
   both footer hint variants now name `Space mark`. The 140-col hint
   test still passes (`B prune` kept in the full hint). FIXED.

4. LOW (R-35 evidence): the render subject for the cleanup confirm
   showed only the cursor item even when a marked multi-select was
   pending, so the y/yb confirm could claim the wrong scope. Now the
   subject names the pending set (1 item vs `N cleanup items`) and
   appends `(yb also deletes branches)` exactly when the option is
   offered. No test asserts the subject text yet; covered indirectly
   by `cleanup_pending_items` tests. NOTE.

5. LOW (R-31): docs gap. The TUI cleanup view was entirely undocumented
   (features.md line 103 listed five Git tabs, no cleanup), and the
   0.7.9 release notes covered only the webui half of the feature.
   Added both: the Git screen line now documents
   Space/mark/x/y/yb/B/parallel/gate, and release notes gain the TUI
   paragraph. FIXED.
