## Findings

1. HIGH (R-26, C-2): closing the last tab of a split pane left a blank
   half-pane on screen. Terminal close (poll prune, forgetClosedSelection,
   closeTab), editor close, git close, and cross-leaf drag-out all emptied
   leaves without collapsing the tree. A control surface that exists with
   nothing to control.
   FIXED: new `collapseEmptyLeafInTree` + `collapseLeafForClosedTab`
   drops the emptied split leaf, promotes the sibling, refocuses the
   survivor. By-design empty split siblings and single-leaf trees keep
   the New terminal card. Wired into editor/git close, `movePaneTabTo`,
   `moveActiveTabToNextPane`, sync prune, and all three terminal close
   flows (core.js, worktrees.js).
   Tests: +4 in `desktop_workspace_panes_split.test.mjs`, prune test
   updated in `desktop_workspace_panes.test.mjs`.

2. HIGH (R-32, C-4): the footer no-sleep menu opened downward from a
   button at the viewport bottom edge: the popover rendered off-screen
   and fought the terminal area for pointer space.
   FIXED: footer-scoped rule in `chrome.css` flips the drop up
   (`bottom: calc(100% + 6px)`).

3. HIGH (R-03, C-4): the session manager card had no height budget: a
   long session list pushed the create/cleanup rows off the viewport and
   nothing scrolled. The card overflowed its overlay in both themes at
   any list length past the fold.
   FIXED: `workspaces.css` caps the card at `calc(100% - 64px)` of the
   fixed overlay (percentage, not vh: the overlay starts below the
   header), flex column with hero pinned, list section gets
   `min-height: 0` + `overflow-y: auto` + `overscroll-behavior: contain`.
   Create/cleanup rows stick to the bottom of the scroll area so they
   stay reachable with a long list.

4. HIGH (R-03, C-4): the pane actions menu opened at `rect.bottom + 4`
   unconditionally: a strip near the viewport bottom pushed it
   off-screen.
   FIXED: `positionPaneMenu` measures after the first position lands;
   if the drop would cross the viewport minus 8px margin, it flips above
   the button. Fake DOMs without layout metrics are no-ops, existing pane
   menu tests pass unchanged.

5. HIGH (R-32, C-4): the no-sleep menu had no Escape path, no
   `aria-haspopup`/`aria-expanded`, no `role="menu"`, and keyboard focus
   stranded on hidden options after picking a mode.
   FIXED: Escape closes an open no-sleep menu ahead of the modal cascade
   and restores focus to the toggle. Toggle syncs `aria-expanded`,
   opening focuses the first option, mode pick and outside-close return
   focus to the control, menu carries `role="menu"`.
   Tests: app_core/app_boot/app_load suites (359 tests) pass.

6. Verified OK (no finding): modal Tab focus trap covers settings,
   worktree create/open, workspace create, search palette, question
   modal; every modal has Cancel and X buttons; session manager backdrop
   click closes; question modal has full dialog aria. Checked against
   `bindings.js` and modal markup, covered by existing suites.
