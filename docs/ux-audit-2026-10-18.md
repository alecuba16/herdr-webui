# Desktop UX audit

Date: 2026-10-18. Branch `master`. Scope: desktop webui (JS + CSS assets),
read-only sweep for interaction defects, then fixes with tests. Every
finding below was confirmed against direct code reads; every fix is
covered by the node suite (`node --test src/assets/*.test.mjs`, 1254
pass) and `cargo test` stays green.

## Findings and fixes

| # | Finding | Where | Fix | Tests |
|---|---|---|---|---|
| U1 | Closing the last tab of a split pane left a blank half-pane on screen. Terminal closes (poll prune, forgetClosedSelection, closeTab), editor closes, git closes, and cross-leaf drag-out all emptied leaves without collapsing the tree. | `workspace_panes.js` sync/move/close paths | New `collapseEmptyLeafInTree` + `collapseLeafForClosedTab`: emptied split leaf is dropped, sibling promoted, survivor takes focus. By-design empty split siblings and single-leaf trees are kept. Wired into editor/git close, `movePaneTabTo`, `moveActiveTabToNextPane`, sync prune, and all three terminal close flows (core.js, worktrees.js). | `desktop_workspace_panes_split.test.mjs` +4 tests, `desktop_workspace_panes.test.mjs` prune test updated |
| U2 | The footer no-sleep menu opened downward from a button at the viewport bottom edge: the popover rendered off-screen and fought the terminal area for pointer space. | `chrome.css` `.no-sleep-menu` | Footer-scoped rule flips the drop up (`bottom: calc(100% + 6px)`). | Manual geometry check; CSS only |
| U3 | The session manager card had no height budget: a long session list pushed the create/cleanup rows off the viewport and nothing scrolled. | `workspaces.css` `.session-card` | Card capped at `calc(100% - 64px)` of the fixed overlay, flex column; hero pinned, list section gets `min-height: 0` + `overflow-y: auto` with `overscroll-behavior: contain`. The create/cleanup rows stick to the bottom of the scrollable list so they stay reachable. | Manual geometry check; CSS only |
| U4 | The pane actions menu (⋮) opened at `rect.bottom + 4` unconditionally: a strip near the viewport bottom pushed it off-screen. | `workspace_panes.js` `positionPaneMenu` | After the first position lands, measure the menu; if the drop would cross the viewport minus 8px margin, flip it above the button. | Existing pane menu tests still pass; fake DOMs without layout metrics are no-ops |
| U5 | The no-sleep menu had no Escape path, no `aria-haspopup`/`aria-expanded`, no `role="menu"`, and keyboard focus stranded on hidden options after picking a mode. | `core.js` `noSleepControlHtml`, `closeNoSleepMenus`; `bindings.js` click delegation, Escape cascade | Escape closes an open no-sleep menu ahead of the modal cascade and restores focus to the toggle. Toggle syncs `aria-expanded`, opening focuses the first option, mode pick and outside-close return focus to the control, menu carries `role="menu"`. | `app_core`/`app_boot`/`app_load` suites (359) pass |
| U6 | Verified OK (no fix needed): modal Tab focus trap covers settings, worktree create/open, workspace create, search palette, question modal; every modal has Cancel and ✕ buttons; session manager backdrop click closes; question modal has full dialog aria. | `bindings.js` Tab trap, modal markup | none | Existing suites |
