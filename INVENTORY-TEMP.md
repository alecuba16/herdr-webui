## 1. What this product is

Rust Axum server that serves an embedded browser UI (desktop + mobile layouts)
for terminal workspaces, worktrees, Git operations, and file browsing. Ships a
built-in terminal multiplexer backend plus a first-party TUI client
(`herdr-webui-tui`). Optional compatibility with an external Herdr daemon.

```
Browser (desktop/mobile vanilla JS) ──HTTP/WS──> Axum WebUI server
                                                   ├── Built-in backend (PTY, git CLI, FS)
                                                   ├── External Herdr bridge (compat)
                                                   ├── Git UI API (/api/git-ui/*)
                                                   ├── File browser API (/api/file-browser/*)
                                                   └── Static assets (include_str!)
TUI (bin/herdr-webui-tui) ──backend_client──> Built-in control/terminal sockets
```

## 2. Tech decisions (as implemented today)

| Area | Decision |
| --- | --- |
| Backend | Rust + Axum, single `main.rs` server (13,865 lines monolith), embedded assets via `include_str!`/`include_bytes!` from `src/assets.rs` |
| Frontend | Vanilla JS/CSS, no framework, no build step for the main shell; vendor bundles (CodeMirror, wterm/Ghostty, marked, DOMPurify, mermaid) checked in and generated by `scripts/build_*_assets.mjs` |
| Bundle model | Desktop/mobile split with `src/assets/shared/` for cross-layout modules; `assets.rs` concatenates `desktop/app_js/*` → `/assets/desktop/app.js` (same for CSS, git-ui JS/CSS) |
| Backend protocol | Built-in backend: newline-delimited JSON control socket + `protocol.rs` frame codec for terminal attach; external Herdr: HTTP/WS proxy with protocol version 22 gates |
| Terminal renderer | wterm (JS core, default) or Ghostty core (WASM); shared `terminal_adapter.js` boundary for desktop/mobile/temp terminals |
| Editor | CodeMirror, preloaded before `editor.js`; per-workspace editor instance cache with signature-based reattach |
| Agent detection | argv/process-tree labels + screen-text fallback, split by agent into `builtin_detection/` (22 agents: Amp, Antigravity, Claude, Claurst, Cline, Codex, Cursor, Devin, Droid, Gemini, Copilot, Grok, Hermes, Jcode, Kilo, Kimi, Kiro, Maki, OpenCode, Pi, Qoder CLI, Qwen) + jcode OSC 9 structured side-channel |
| Auth | Cookie session (`herdr_web_session`), username/password required for non-localhost binds; localhost bypass option |
| Session manager | Multi-backend sessions in one WebUI process; `x-herdr-backend` header + `backend=` query param routing; disabled backends are rejected, never silently rerouted |
| Events | Built-in event hub (`builtin_events.rs`) publishes Herdr-shaped JSON; WebUI skips legacy 5s polling for built-in; external keeps subscription + polling fallback |
| Git ops | All through the system `git` CLI (no libgit2); server-side porcelain scan + parent-status propagation |
| Search | Unified header search; backend-owned file/folder/content search with pagination, ignore rules, caps, regex validation |
| Persistence | Browser `localStorage` (`herdr-web-options`) via shared `HerdrOptions` module; server `webui-settings.json` for bind/auth/backend/default folder |
| TUI modularity | Explicit SOLID boundaries: `backend_client.rs` (transport) / `tui.rs`+`tui_model.rs` (state) / `tui_render.rs` (Ratatui) / `tui_terminal.rs` (ANSI) / `bin` (wiring) |
| Testing | Rust `cargo test`; frontend `node --test src/assets/*.test.mjs` (23 test files); real-browser CDP e2e acceptance scripts in `scripts/e2e/` |
| CI | GitHub Actions: webui-ci.yml (fmt, clippy -D warnings, tests, release build) |

## 5. SOLID / modularity findings (graph-verified)

### Critical (SOLID violations)

1. **`src/main.rs` is a 13,865-line god-module** — 152 functions, 56 types,
   224 routes in one file: CLI parsing, TLS, auth, settings persistence,
   session registry, all HTTP handlers, terminal WS bridge, install helpers,
   and 177 inline tests. Single-Responsibility violation at file scale.
   The prior audit (docs/code-quality-audit.md) already deferred this split.
2. **`src/builtin_backend.rs` (6,966 lines) mixes 4 responsibilities**:
   runtime state, PTY management, socket request dispatch, and agent status
   detection with 22 hand-written `detect_*_status` functions (each agent has
   its own function with duplicated loop/scan structure). The
   `builtin_detection/` split covers identity, not status.
3. **Desktop `git_ui.js` (4,344 lines)** mixes view state, diff rendering,
   shortcuts, file actions, and API glue in one IIFE. `git_ui/log.js` was
   already extracted; the remainder is still one closure.
4. **Desktop `core.js` (4,008 lines)** mixes options, settings UI, session
   chrome, no-sleep, notifications, and app state.
5. **`mobile/app.js` (2,075 lines)** mixes screens, search, sessions, Git
   status view, and event wiring; the desktop counterpart was split but
   mobile was not.

### Structural smells (graph metrics)

- **Hotspot fan-in**: `desktop/git_ui.js` `active` (154), `render` (101),
  `menuAction`; desktop `core.js` `el` (113) — single closure-global state
  pattern with everything calling everything.
- **Complexity**: `temp_terminal.js createTempTerminalManager` (cyclomatic
  202 / cognitive 271, 991 lines) and `createSessionInstance` (180/245, 806
  lines) are the worst functions in the repo. `mobile/file_browser.js create`
  (159/196, 980 lines) follows. These are closures-returning-managers, so
  the cyclomatic number includes nested functions — but each is still a
  800–1000-line unit.
- **Duplicated `escapeHtml`** in 4 bundles (desktop terminal, shared core,
  temp terminal, mobile core) — the shared module exists but desktop
  `app_js/terminal.js` and `temp_terminal.js` keep private copies.
- **7 independent `api()` client definitions** across bundles (desktop core,
  file_browser, git_ui, lsp_settings, directory_picker, mobile app, shared
  lsp) — each reimplements auth-header/backend-target/session handling
  instead of depending on one shared HTTP client module.
- **Duplicated attention/notifications logic**: desktop `bindings.js` +
  `core.js` vs mobile `attention.js` implement tone + notifications
  separately.
- **Worktree flows duplicated**: desktop `worktrees.js` (1,162) vs mobile
  `worktrees.js` (228) share discovery/create/open semantics but not code.

### Parity issues (docs vs code drift)

1. **Docs claim "Mobile has read-only browse/preview parity"** for files
   (features.md L137) and "read-only Git status + diffs" (development.md
   L79), but mobile `file_browser.js` implements full editing, save with
   hash guard, rename, delete, and new-file flows, and mobile `app.js` calls
   `/api/git-ui/stage`, `unstage`, `discard`, `switch` (verified wired to
   buttons + confirm dialogs). Docs are stale; the code is ahead of the
   docs.
2. **Mobile lacks** (undocumented gaps, not marked intentional): recent
   workspaces, no-sleep, notification scope, agent sorting, stuck-working
   dismiss, panel activity labels, editor find/replace, split panes,
   markdown preview toggle UI, directory picker.
3. **Desktop lacks** nothing observed vs mobile, except mobile-specific
   layout features.

### Confirmed functional defect (desktop session targeting)

`git_ui.js`, `file_browser.js`, `directory_picker.js`, and `lsp_settings.js`
each define a private `api()` helper that does NOT attach
`x-herdr-session`/`x-herdr-backend` headers (only `credentials:
"same-origin"`), while desktop `core.js` api() attaches them via
`apiOptions()`. Consequences (verified against `src/main.rs`
`api_for_headers_ensured` / `worktrees` handler):

- `git_ui.js` calls `/api/worktrees`, which is session-scoped → the Git
  drawer's worktree list targets the **default session/backend** instead of
  the pinned one. With a non-default session selected, Git drawer worktree
  actions can hit the wrong backend.
- The same files' calls to `/api/git-ui/*`, `/api/file-browser/*`, and
  `/api/lsp/*` are cwd-scoped server-side, so the missing headers are mostly
  harmless there — but the inconsistency is a trap: any future
  session-scoped route added to those modules will silently misroute.
- 401 handling also diverges: core.js redirects to `/` on 401; the private
  copies do not, so auth-expired Git/Files interactions show raw errors
  instead of the login flow.

This is both a parity bug (desktop lazy modules vs desktop core vs mobile,
which correctly injects the main `api()` into all submodules) and a
DRY/SOLID argument for a single shared HTTP client module.

## 6. Refactor proposal (SOLID + parity)

Phased, each phase shippable and covered by the existing test suites:

**Phase 0 — protect the flow (no behavior change)**
- `just check` (fmt + clippy -D warnings + all tests) as the gate.

**Phase 1 — Rust backend split (SRP at module scale)**
- `src/main.rs` → `web/` module tree: `web/mod.rs` (router assembly),
  `web/auth.rs`, `web/settings_server.rs`, `web/sessions.rs`,
  `web/tls.rs`, `web/install.rs`, `web/routes/{workspace,tab,pane,git,file,search,...}.rs`,
  `web/ws/{terminal,events}.rs`. Keep `main()` thin in `src/main.rs`.
- `src/builtin_backend.rs` → `builtin/` module tree: `runtime.rs` (state),
  `pty.rs`, `dispatch.rs`, `status/` (table-driven agent status rules
  replacing 22 `detect_*_status` functions, reusing `builtin_detection`
  patterns).
- Update `src/assets.rs` concat lists only if asset paths change (they don't
  in this phase).

**Phase 2 — frontend shared modules (DRY between layouts)**
- Extract `shared/http.js` (one `api()` client: auth cookie, backend-target
  header, session header, error normalization) replacing the 7 copies.
- Extract `shared/escape.js` or extend `shared/core.js` exports; delete the
  duplicate `escapeHtml` copies.
- Extract `shared/attention.js` (tone + notifications) used by both layouts.
- Extract `shared/worktree_flows.js` (discovery/create/open semantics) with
  layout controllers keeping only rendering.
- Wire into `assets.rs` concat and `app_boot.js` load order before layout
   bundles.

**Phase 2b — decompose the monolith closures**
- `desktop/git_ui.js` → `desktop/git_ui/{views,status,diff,log_actions,shortcuts,api}.js`
  modules concatenated (mirroring the successful `log.js` extraction).
- `desktop/core.js` → extract `desktop/app_js/{options_apply,settings_modal,session_chrome,notifications,nosleep}.js`.
- `mobile/app.js` → `mobile/{screens,search,sessions,git_status,events}.js`.
- `shared/temp_terminal.js` → split manager vs session-instance factory.

**Phase 2c — parity (behavior change, deliberate)**
- Mobile: recent workspaces, no-sleep control, notification scope,
  agent sorting, stuck-working dismiss.
- Update `docs/features.md` and `docs/development.md` parity sections to
  match reality (mobile file/Git mutations exist).
- Docs parity table (§4) to be the source of truth going forward.

**Phase 3 — verification**
- `just check` after each phase; run e2e acceptance scripts
  (`just e2e`, `just git-e2e`, `just content-search-e2e`, `just theme-e2e`,
  `mobile-edit` acceptance) where environments allow.
- Re-index graph, re-run complexity/hotspot queries, update this inventory
  and finally fold conclusions into `docs/code-quality-audit.md`, then
  delete this file.

## 8. Code review (code-review-excellence pass, 2026-09-12)

### Summary

Reviewed the repository at `main` @ a25e8db using the graph index plus direct
source reads of every cited file. Focus: SOLID boundaries, desktop/mobile
parity, security posture, and correctness of the session-routing model.
Validation baseline: `cargo fmt --check` clean, `cargo test` exit 0,
`node --test src/assets/*.test.mjs` 486/486 pass.

### Strengths

- [praise] Clear architectural separation for the TUI stack
  (`backend_client.rs` / `tui.rs` / `tui_render.rs` / `tui_terminal.rs` /
  `bin/herdr-webui-tui.rs`); the docs even name the SOLID boundaries. This
  is the pattern the rest of the repo should copy.
- [praise] `src/git_ui/` was split into 9 focused modules and
  `builtin_detection/` extracted agent identity — the 2026-08-17 audit's
  recommendations landed.
- [praise] Security fundamentals are correct where it matters:
  `require_auth` on every route, constant-time credential and token
  comparison, path canonicalization + `starts_with(root)` guards on file
  ops, hash-guarded file saves, permissions `0o600` on the settings file,
  destructive Git actions confirmed server-side.
- [praise] Parity architecture is deliberate where it exists: shared
  modules (`file_tree.js`, `workspace_search.js`, `file_content_search.js`,
  `editor.js`, `terminal_adapter.js`, `temp_terminal.js`) keep controllers
  thin, and mobile injects the session-aware `api()` into all submodules.
- [praise] Test discipline: 486 frontend assertions, hundreds of Rust
  tests, plus real-browser CDP acceptance scripts for edit/git/search/theme
  flows on both layouts.

### Required Changes

- [blocking] **Desktop lazy modules drop session/backend headers.**
  `git_ui.js`, `file_browser.js`, `directory_picker.js`, `lsp_settings.js`
  each define a private `api()` without `x-herdr-session`/
  `x-herdr-backend`, unlike desktop `core.js` and all mobile modules.
  `git_ui.js` calls session-scoped `/api/worktrees`, so with a non-default
  session pinned the Git drawer reads worktrees from the wrong backend.
  Fix: one shared HTTP client module (see Phase 2), or at minimum inject
  `apiOptions` from core into the lazy modules. Also add the 401 redirect
  behavior for consistency.
- [important] **Docs/feature drift on mobile capability.** `docs/features.md`
  and `docs/development.md` describe mobile Files/Git as read-only, but
  mobile already ships editing, save, rename, delete, new-file, and Git
  stage/unstage/discard/switch. Users cannot trust the docs; parity work
  can't be tracked against them. Fix: update the Desktop and Mobile Parity
  section and features.md to match reality, then keep the §4 table as the
  source of truth.
- [important] **`src/main.rs` (13,865 lines) and `src/builtin_backend.rs`
  (6,966) violate SRP at file scale.** Both were already deferred in the
  2026-08-17 audit. Every new route/feature touches the same two files,
  and merge conflicts plus test density (177 inline tests in main.rs)
  make review harder. This is the highest-leverage modularity work
  available and should be sequenced before adding new server features.

### Suggestions

- [suggestion] Replace the 22 hand-written `detect_*_status` functions in
  `builtin_backend.rs` with table-driven rules (pattern lists + status
  mapping), reusing the `builtin_detection/` structure. `osc_title_status_for_agent`
  (cyclomatic 34) and `detect_qwen_status` (27) show the duplication cost.
- [suggestion] Decompose the 800–1000-line closure factories:
  `temp_terminal.js createTempTerminalManager` (cyclomatic 202, 991
  lines), `createSessionInstance` (180, 806), `mobile/file_browser.js create`
  (159, 980), `desktop/core.js applyOptions` (65), `mobile/settings.js
  createMobileSettings` (65). Extract inner functions to module scope with
  explicit state parameters.
- [suggestion] Auth cookie lacks `Secure` attribute when the server runs
  TLS (`--https on`). Add `Secure` to `Set-Cookie` when TLS is active.
  Low exploitability (local-first tool) but cheap to fix during the auth
  extraction.
- [suggestion] Add a lint/CI guard that forbids new private `api()`
  definitions in bundles (simple grep assertion like the existing
  `assets.rs` tests) so the header bug can't regress.
- [nit] Duplicate `escapeHtml` in 4 bundles; route desktop
  `app_js/terminal.js` and `temp_terminal.js` through the shared
